## ۲) خلاصهٔ محصول

کاربر تاریخ/ساعت/محل تولدش را وارد می‌کند؛ موتور Swiss Ephemeris **موقعیت دقیق سیاره‌ها، خانه‌ها و زوایا** را در آن لحظه محاسبه می‌کند (۱۰۰٪ قطعی، بدون AI)؛ یک چارت تعاملی SVG + پیش‌نمایش رایگان ۳-۵ بینش نشان داده می‌شود؛ کاربر یکی از ۵ پلن را می‌خرد؛ و یک **گزارش اختصاصی ۱۳ حوزه‌ای (۳۰-۶۰ صفحه PDF/Word فارسی)** با DeepSeek V4 Pro تولید می‌شود — هر بینش با «شاهد نجومی» (کدام سیاره/خانه/زاویه) و با کنترل کیفیت خودکار.

**قانون طلایی:** محاسبات نجومی هرگز با AI انجام نمی‌شود (دقت ماشین)؛ AI فقط متن می‌نویسد (عمق انسان).

**تعهد محصول:** هیچ فال/پیش‌گویی/طالع‌بینی‌ای؛ زبان «تأمل، خودشناسی، آموزشی».

## ۳) معماری کلان و جریان کاربر

```
کاربر ──► فرم تولد (تاریخ شمسی/میلادی + ساعت + شهر از ۳۳۷ شهر)
   └─► POST /api/charts ──► محاسبه با Swiss Ephemeris ──► Chart ذخیره می‌شود
   └─► صفحهٔ چارت: دایرهٔ زایچه SVG + سه‌گانه (خورشید/ماه/طالع) + ویجت عناصر/خانه‌ها + پیش‌نمایش رایگان
   └─► انتخاب پلن (پایه/کامل/طلایی/سیناستری/ماهانه) ──► سفارش ──► زرین‌پال
   └─► وب‌هوک پرداخت ──► اشتراک/دسترسی فعال می‌شود ──► سفارش وارد صف ARQ می‌شود
   └─► کارگر گزارش: ۱۳-۱۴ بخش را یکی‌یکی می‌نویسد + QA خودکار + PDF/Word
   └─► دانلود از Cloudflare R2 (لینک موقت presigned)
```

**اجزای جانبی:**
- **ربات‌های تلگرام + بله** (`@Voice_clone_real_bot` / `@VoieAiToolsbot`) — کل خرید و گزارش بدون تایپ، تمام‌دکمه‌ای.
- **AI Chat** — بعد از خرید، سؤال از گزارش (با بازیابی RAG از گزارش).
- **ترانزیت هفتگی** — هر هفته ربات خلاصهٔ تأثیر سیارات روی چارت کاربر را می‌فرستد (چرا کاربر برگردد).
- **یابندهٔ ساعت تولد (Rectify)** — ساعت نامشخص را با رویدادهای زندگی حدس می‌زند.
- **سیناستری** — سازگاری دو چارت (نمرهٔ ۴ حوزهای + ۲۵+ ارتباط سیاره‌ای).
- **آسمان امروز** — وضعیت روزانهٔ سیارات/فاز ماه/جنبه‌ها (صفحهٔ عمومی رایگان).
- **مقالات/آموزش/راهنما/FAQ** — محتوای آموزشی SEO.

## ۸) موتور نجومی

- `pyswisseph` با فایل‌های ephemeris محلی در `ephe/` (بدون اینترنت).
- محاسبه: موقعیت ۱۰ سیاره + گره‌ها، ۱۲ خانه (پلاسیدوس)، جنبه‌های اصلی/فرعی، طالع (ASC)، MC.
- سیستم: **سایدریال (لاهیری)** — مطابق سنت اخترشناسی ایرانی.
- تقویم: شمسی (jalaali) و میلادی.
- خروجی سه‌گانهٔ اصلی: خورشید/ماه/طالع.
- **۲۱ تست «طلایی»** در `golden_data.py`: مقادیر مرجع محاسبه‌شده و ثبت‌شده (مثلاً چارت مهدی: خورشید اسد ۲۹°۴۲′، طالع اسد، ماه حوت ۲۱° در خانهٔ ۸) — برای اطمینان از عدم رگرسیون.

## ۹) موتور تولید گزارش

1. سفارش پرداخت‌شده → `Report` با وضعیت `queued` در صف ARQ.
2. کارگر، ۱۳-۱۴ بخش (شخصیت، شغل، عشق، خانواده، سلامتی، خلاقیت، تحصیل، روابط، مالی، معنویت، کارما/زحل، فرهنگ-اسلامی، ترانزیت…) را **یکی‌یکی** با DeepSeek V4 Pro می‌نویسد.
3. هر بخش **QA خودکار** (`qa.py`): فارسی روان؟ ارجاع به دادهٔ نجومی؟ طول کافی؟ اگر ضعیف → بازنویسی (حداکثر ۲ بار).
4. **قوانین بینش** (`rules.py`): هر بینش باید «شاهد نجومی» داشته باشد (سیاره در خانهٔ X با زاویهٔ Y) — قابل ردیابی.
5. مونتاژ PDF (reportlab + وزیرمتن، RTL، ۳۰-۶۰ صفحه) و Word.
6. آپلود به R2؛ لینک presigned موقت؛ فقط مالک واقعی (چک chart_id + session) دانلود می‌کند.
7. هزینهٔ هر فراخوانی در `LLMRun` ثبت می‌شود (داشبورد: هزینهٔ ۷ روز اخیر + به تفکیک پروایدر).

**بخش ویژه:** «فصل فرهنگی-اسلامی» — تقویم قمری و مفاهیم فرهنگی (مزیت رقابتی بدون رقیب).

## ۱۱) ربات‌های تلگرام و بله

- دو پلتفرم با **یک هندلر** (`bots/handler.py`)؛ state ماشین در `BotState`.
- **تمام‌دکمه‌ای:** هیچ دستور تایپی در هیچ مرحله‌ای؛ بعد از انتخاب صدا/مدل فقط «آهنگ/متن را بفرست».
- آیتم‌های تاریخچه = دکمه (tap → جزئیات + دانلود).
- وب‌هوک: تلگرام `setWebhook` با secret_token؛ **بله `tapi.bale.ai` (نه api.bale.ai)** و بدون secret_token (بله آن را نمی‌فرستد؛ اگر ست شود هر آپدیت ۴۰۱ می‌شود).
- جزئیات فنی: `parse_mode=HTML` (Markdown با `_` در شناسهٔ صداها می‌شکست)، کالبک `tts_v_<id>` / `model_<id>`.

## ۱۲) گفت‌وگو با هوش مصنوعی

- فقط برای دارندگان پلن طلایی/ماهانه (access check + سهمیهٔ روزانه).
- معماری: `retrieval.py` — جستجوی بخش‌های مرتبط گزارش (RAG سبک روی متن گزارش) → پرامپت با زمینه → DeepSeek V4 Flash.
- تاریخچه در `ChatMessage`؛ UI صفحهٔ `/chat/{chart_id}` با HTMX/Alpine.
- **پروایدرهای پشتیبانی‌شده (جدید، از پنل ادمین):** `{part}_llm_provider` = `go` / `deepseek` / `auto` (پیش‌فرض auto: اول OpenCode Go، در صورت خطا DeepSeek مستقیم اگر کلید داشته باشد).
- **مدل‌ها:** گزارش = `deepseek-v4-pro`، چت/پیش‌نمایش = `deepseek-v4-flash`.
- **قانون مهم:** کلیدهای Gemini **هرگز** برای چت محصول استفاده نمی‌شوند (فقط ابزار داخلی vision عامل).

## ۱۳) SEO و محتوای آموزشی

- **۵۰ مقاله** (`articles.json`) با دسته‌بندی (۸ دسته: آموزش نجوم، برج‌ها، ترانزیت، خانه‌ها، سازگاری، سیارات، شغل، ماه)، excerpt، keywords، meta، تصویر + بندانگشتی webp، بنر SVG.
- **صفحهٔ آموزش** `/learn`: ۳ راهنما + ۱۰ سیاره + ۱۲ خانه + ۱۲ برج (هرکدام چند بخش ساختاریافته).
- **محتوا:** هر مقاله ≥۶۰۰ کاراکتر و ≥۳ بخش (چک‌شده: هیچ مقالهٔ ناقصی نیست).
- `sitemap.xml` (۶۵+ URL) + `robots.txt` + canonical + og tags.
- **باگ مهم فیکس‌شده:** ۸ قالب از `{% block meta %}` استفاده می‌کردند در حالی که base.html بلاک `{% block description %}` دارد → متا دیسکریپشن هیچ صفحه‌ای سرو نمی‌شد. همه اصلاح شدند و روی live تأیید شد (هر صفحه متا دارد).
- **پیشنهاد قبلی:** کش Redis برای چت (~۵۰٪ صرفه‌جویی)، مقالات بیشتر، تصاویر FLUX.

## ۱۴) پنل مدیریت

- لاگین با PIN (HMAC، کوکی httponly، rate-limit بروت‌فورس، رمز عددی — چون مالک با گوشی فارسی تایپ می‌کند).
- **KPI:** درآمد ۷ روزه، سفارش‌ها به تفکیک وضعیت، پیام‌های چت امروز/کل، هزینهٔ AI ۷ روزه به تفکیک پروایدر.
- **وضعیت AI:** مدل فعال هر بخش + سلامت پروایدرها.
- **بخش جدید «پروایدر و مدل هوش مصنوعی»:** برای گزارش/چت/پیش‌نمایش: انتخاب پروایدر (خودکار/فقط Go/فقط DeepSeek) + مدل (pro/flash) + دکمهٔ «تست اتصال» (فراخوانی واقعی و نمایش latency).
- **کلیدها و رازها:** `secret_store` — مقدارها رمزنگاری‌شده (Fernet، کلید مادر در `.env`) در جدول `Secret`؛ fallback به متغیر محیطی؛ بعد از ذخیره نیاز به ری‌استارت.
- ویرایش پلن‌ها (قیمت/فعال)، پرامپت‌ها (نسخه‌بندی + فعال‌سازی)، بازتولید گزارش ناموفق، مشاهدهٔ کاربران/سفارش‌ها/لاگ حسابرسی.

## ۱۵) امنیت

- کوکی ادمین: HMAC امضاشده + httponly + secure + samesite=lax.
- **IDOR فیکس‌شده:** گزارش/چت فقط برای مالک چارت (session) — لینک مستقیم کافی نیست.
- **دانلود امن:** فایل‌های R2 presigned + چک مالکیت.
- محدودیت نرخ (rate limit) برای ۴ سرویس گران + لاگین ادمین + OTP؛ `--proxy-headers` برای IP واقعی (فیکس شد).
- سانسور ورودی‌ها (prompt injection) در چت/گزارش.
- هش HMAC برای کوپن/رفرال.
- هیچ سکرتی در git نیست (کلیدها در `.env` + DB رمزنگاری‌شده؛ `.env.age` رمزگذاری‌شده با age).
- پنل ادمین `noindex,nofollow`؛ سکرت‌ها فقط با reveal صریح.

## ۲۱) ریسک‌ها و نقاط ضعف صادقانه

1. **مرچنت زرین‌پال متصل نیست** — درآمدزایی واقعی هنوز صفر؛ کل جریان پرداخت تا تست واقعی ناقص است.
2. **OTP پیامکی واقعی نیست** — کلید Kavenegar نگرفته شده؛ فعلاً کد dev (گلوگاه برای ثبت‌نام واقعی).
3. **وابستگی به یک پروایدر AI (OpenCode Go)** — اگر اشتراک/کلید قطع شود، بدون fallback واقعی می‌مانیم (fallback DeepSeek مستقیم نیاز به کلید دارد که هنوز تنظیم نشده).
4. **دامنهٔ رسمی `zayche.io` خریداری نشده** — برند روی دامنهٔ زیرشاخهٔ negar.io است.
5. **تست موبایل واقعی انجام نشده** — تست‌ها با viewport مرورگر است؛ مشکلات گوشی واقعی (مخصوصاً PWA و ربات) ممکن است دیده نشود.
6. **هیچ کشی برای چت نیست** — هر سؤال هزینهٔ LLM دارد (پیشنهاد: Redis cache ~۵۰٪ صرفه‌جویی).
7. **حجم محتوای SEO** (۵۰ مقاله) برای رقابت کافی نیست — نیاز به صدها مقاله + تصاویر اختصاصی FLUX.
8. **نرخ تبدیل و UX نهایی با دیتای واقعی سنجیده نشده** (Umami فعال است ولی دادهٔ کمی دارد).
