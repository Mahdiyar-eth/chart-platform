## F-19 residual (P1) — cleanup سیناستری fail-closed شد ✅

**ادعا:** compensation در `except` بود و خطای خودش بلعیده میشد؛ اگر خود
cleanup fail میکرد، کاربر 400 میگرفت و charts/profiles (مخصوصاً Guest
Person B بدون user_id و بدون مسیر حذف) ممکن بود orphan بمانند — «never
orphaned» نقض میشد.

**راستیآزمایی:** ✅ درست — `except Exception: session.rollback()` سپس
`raise HTTPException(400, ...)` — خطای cleanup نامرئی بود.

**فیکس:**
- cleanup موفق → خطای پرداخت اصلی (400)
- cleanup ناموفق → **502** + پیام «دادههای سیناستری پاک نشد — با پشتیبانی
  تماس بگیرید» + **audit** (`synastry.cleanup_failed` با جزئیات) — وضعیت
  ناتمام برای اپراتور قابلردیابی است، نه بلعیدهشده.

**اثبات:** تست جدید — monkeypatch روی Session.delete که fail شود →
پاسخ 502 (نه 400) + پیام پشتیبانی.
