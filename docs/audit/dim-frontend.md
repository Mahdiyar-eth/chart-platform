# بعد: فرانت‌اند

پاسخ مدل: go/deepseek-v4-pro

## تحلیل فرانت‌اند — چارت تولد (Jinja2/Alpine/HTMX/PWA)

### محدودیت این تحلیل
در ورودی، فقط `app/main.py` و سند OVERVIEW داده شده است. فایل‌های `templates/*.html`، `static/js/*.js`، `tailwind_inline.css`، `app/security.py` و `app/seo/content.py` ارائه نشده‌اند.  
بنابراین تحلیل دقیق اسکریپت‌ها، وضعیت Alpine، رندر HTMX، مدیریت خطای فرم‌ها و محتوای قالب‌ها **نامشخص** است و هر جا لازم باشد، صریح می‌گویم.

---

## یافته‌های کلیدی با اولویت

### P0 — بحرانی

**هیچ P0 قطعی در لایه‌ی فرانتِ قابل مشاهده در کد موجود شناسایی نشد.**  
اما دو ریسک بالا وجود دارد که اگر در قالب/JS تأیید شوند، می‌توانند بحرانی باشند:

- **CSP با `unsafe-inline/eval`**  
  در OVERVIEW ذکر شده است. این موضوع مستقیماً لایه‌ی فرانت را تحت تأثیر قرار می‌دهد. اگر CSP واقعاً `unsafe-eval` دارد، عملاً محافظت در برابر XSS از طریق قالب‌ها/جاوااسکریپت تضعیف می‌شود.  
  مرجع: `app/main.py` خط ~۶۵ — `app.middleware("http")(security_guard)` (خود تنظیمات در `app/security.py` است که در دسترس نیست).  
  **وضعیت:** نیازمند بررسی `app/security.py` است، ولی طبق OVERVIEW مستند شده است.

- **عدم الزام پلن گلد برای چت**  
  در API چت، فقط وضعیت پرداخت سفارش بررسی می‌شود، نه `plan_key`. اگر فرانت چت را فقط برای گلد نمایش دهد، کاربر با دانستن URL می‌تواند با هر پلن دیگری هم چت کند.  
  مرجع:  
  `app/main.py` — `@app.get('/api/chat/access/{chart_id}')` و `@app.post('/api/chat')`  
  در هر دو:
  ```python
  select(Order).where(Order.chart_id == chart_id, Order.status == "paid")
  ```
  فیلتر `plan_key == "gold"` یا سیاست دقیق دسترسی وجود ندارد.  
  این یک نشت هزینه/قابلیت است و باید در بک‌اند اصلاح شود تا فرانت بتواند رفتار درست داشته باشد.

### P1 — مهم

#### ۱. ویجت دونات عناصر، داده‌ی غلط می‌گیرد
در `chart_page` وقتی ویجت دونات عناصر ساخته می‌شود:
```python
element_donut_svg({p.get("sign_fa", ""): 1 for p in planets.values()})
```
چون کلید dictionary نام برج است، اگر چند سیاره در یک برج باشند، مقدار همان `1` باقی می‌ماند.  
**نتیجه:** ویجت عناصر، تعداد واقعی سیارات در هر برج/عنصر را نشان نمی‌دهد.  
مرجع: `app/main.py` — `@app.get('/chart/{chart_id}')` در رندر `chart.html`.  

**وضعیت:** این یک باگ قطعی در داده‌ی ویجت است. باید شمارش تجمعی بر اساس برج/عنصر ساخته شود.

#### ۲. اسلاگ سنبله در سایت‌مپ اشتباه است
در `sitemap_xml` لیست اسلاگ‌ها چنین است:
```python
("hamal", "sowr", "jowza", "sartan", "asad", "sowza",
 "mizan", "aghrab", "ghows", "jadi", "dalv", "hout")
```
اسلاگ `sowza` برای برج سنبله غیراستاندارد است. نام درست معمولاً `sonbale` یا `sombole` است.  
اگر `app/seo/content.py` از اسلاگ دیگری استفاده کرده باشد، این آدرس در سایت‌مپ به 404 می‌خورد.  
مرجع: `app/main.py` — `@app.get('/sitemap.xml')`.  

**وضعیت:** نیاز به بررسی `app/seo/content.py` دارد ولی نشانه‌ی قوی خطای SEO است.

#### ۳. نبود CSRF برای فرم‌های مبتنی بر کوکی
تمام APIهای POST که با `Form(...)` کار می‌کنند و احراز هویت سشن دارند، هیچ توکن CSRF ندارند.  
این موارد حداقل شامل:
- `@app.post('/api/orders')`
- `@app.post('/api/charts/{chart_id}/report')`
- `@app.post('/api/chat')`
- `@app.post('/api/synastry/order')`

مرجع: `app/main.py` — روت‌های فوق.  
اگرچه `SameSite=Lax` برای بعضی کوکی‌ها ممکن است جلوی حملات cross-site را بگیرد، اما برای اقدامات حساس مالی/محتوایی، CSRF باید صریحاً مدیریت شود.  
**وضعیت:** ریسک فرانت‌اند/امنیتی قابل توجه.

#### ۴. عدم تفکیک خطاهای API برای نمایش در قالب
بسیاری از خطاهای `HTTPException` در `api_create_chart`، `api_create_order` و `api_payment_verify` پیام فارسی مناسبی دارند، اما مشخص نیست فرانت برای خطاهای HTMX/fetch چگونه آن‌ها را نمایش می‌دهد.  
بدون دیدن `static/js` نمی‌توان تأیید کرد که کاربر پیام واضح می‌گیرد.  
**وضعیت:** نامشخص — برای یک محصول RTL با UX خوب، باید بررسی شود.

### P2 — بهبود

#### ۱. سایت‌مپ دستی و ثابت است
`sitemap_xml` لیست ثابتی از URLها را تولید می‌کند و از `app/seo/content.py` خوانده نمی‌شود.  
اگر محتوا اضافه شود، سایت‌مپ به‌روز نمی‌شود.  
مرجع: `app/main.py` — `@app.get('/sitemap.xml')`.

#### ۲. هدر کش برای `api_share_card` مشخص نیست
`api_share_card` می‌گوید “rendered + cached on first request”، اما در کد آن هدر صریح `Cache-Control` دیده نمی‌شود.  
اگر کش داخلی `render_share_card` درست کار نکند، هر درخواست OG card دوباره رندر می‌شود.  
مرجع: `app/main.py` — `@app.get('/api/share/{chart_id}.png')`.

#### ۳. Service Worker فقط فایل را برمی‌گرداند
`sw_file` فایل `sw.js` را با `Cache-Control: no-cache` برمی‌گرداند که برای خود سرویس‌ورکر درست است.  
اما مشخص نیست داخل `sw.js` چه استراتژی کش برای دارایی‌های استاتیک و API دارد.  
اگر `/api` یا صفحات HTML را کش کند، پس از خرید/آپدیت ممکن است کاربر نسخه‌ی قدیمی ببیند.  
مرجع: `app/main.py` — `@app.get('/sw.js')`.

#### ۴. احتمال رقابت در تولید فایل صوتی
`api_report_audio` فایل موقت `/tmp/report-audio-...mp3` را بدون قفل تولید می‌کند.  
اگر دو کاربر هم‌زمان صوتی را درخواست دهند، ممکن است روی یک فایل race شود.  
این مورد بیشتر سمت سرور است ولی بر تجربه‌ی فرانت اثر می‌گذارد.  
مرجع: `app/main.py` — `@app.get('/api/reports/{report_id}/audio')`.

## پیشنهادهای مشخص برای فرانت‌اند

1. **گیت چت را در سرور بر اساس `plan_key` اصلاح کنید.**  
   سپس `/api/chat/access` همان منطق را به فرانت بدهد تا UI هم درست شود.

2. **ویجت دونات عناصر را با شمارش واقعی درست کنید.**  
   قبل از صدا زدن `element_donut_svg`، شمارش تجمعی بر اساس `sign` یا `element` انجام شود.

3. **سایت‌مپ را از `app/seo/content.py` تولید کنید.**  
   اسلاگ سنبله را بررسی و تصحیح کنید. لیست اسلاگ‌ها نباید هاردکد باشد.

4. **برای APIهای POST مبتنی بر کوکی، CSRF token اضافه کنید**  
   یا حداقل کوکی‌های حساس را `SameSite=Strict` کنید. در فرم‌های HTMX/Alpine باید هدر/توکن ارسال شود.

5. **خطاهای HTMX را استاندارد کنید.**  
   از قابلیت `hx-on::response-error` برای نمایش پیام خطای `detail` از FastAPI استفاده کنید.

6. **برای فایل‌های استاتیک از هش نسخه استفاده کنید.**  
   مثلاً `style.css?v=...` تا پس از هر deploy کاربر نسخه‌ی جدید بگیرد.

7. **تست PWA را به CI اضافه کنید.**  
   بررسی کنید `sw.js` صفحات HTML و endpointهای `/api/orders` و `/payment/result` را کش نکند.

## جمع‌بندی این بُعد

معماری فرانت‌اند انتخاب‌شده (Jinja2 RTL + Alpine.js + HTMX بدون بیلد) برای این محصول مناسب است؛ سبک، قابل نگهداری و هماهنگ با نیاز فارسی است.  
اما دو مشکل واقعی در کد موجود دیده می‌شود که مستقیماً روی قابلیت‌های فرانت اثر می‌گذارند:  
- ویجت دونات عناصر داده‌ی غلط نمایش می‌دهد.  
- گیت چت فقط به `status == paid` وابسته است و پلن را در نظر نمی‌گیرد.  

همچنین خطرات CSP و CSRF در صورت تأیید، باید پیش از رشد محصول برطرف شوند.  
برای تحلیل کامل‌تر فرانت‌اند، لازم است فایل‌های `templates/*.html`، `static/js/*.js` و `static/css` نیز ارائه شوند؛ در غیر این صورت بخش‌های مهمی از تجربه‌ی کاربری نامشخص باقی می‌ماند.
