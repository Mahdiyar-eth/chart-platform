## 🔴 P1-1 — «گزارش طلایی» وعده‌اش را تحویل نمی‌دهد (۱۴ اعتبار ≈ ۷۰۰ هزار تومان)

**کاتالوگ می‌فروشد** (`app/db.py:127`):
```
report_gold · «گزارش طلایی (۱۳ بخش + چت ۳۰ روزه + گذر ۱۲ماهه)» · ۱۴ اعتبار
```

**اما در واقعیت فقط یک استحقاق ساخته می‌شود.** `app/entitlements.py` → `_kind_for_action()`:
```python
if action_key.startswith("report_"): return "report"    # ← report_gold هم همین
```

**اثبات زنده** — کاربری که ۱۴ اعتبار داد:
```
خرید report_gold  → 200 · remaining=26
تولید گزارش       → 200 · plan_key=gold        ✅ (این درست است)
دسترسی چت         → {"allowed": false, ...}    ❌ چتی که فروخته شد، باز نمی‌شود

استحقاق‌های واقعی در دیتابیس:
  kind  | quantity | used | source
 report |    1     |  0   | credit      ← فقط همین یک ردیف
```
و `POST /forecast/analyze` هیچ چک استحقاقی ندارد ⇒ همان کاربر برای «گذر ۱۲ماهه»
که بابتش پول داده، **دوباره ۵ اعتبار** پرداخت می‌کند.

**نتیجه:** خریدار طلایی (۱۴ اعتبار) دقیقاً همان چیزی را می‌گیرد که خریدار
`report_full` (۷ اعتبار) می‌گیرد. **دو برابر قیمت، همان تحویل.**

**فیکس:** خرید `report_gold` باید سه استحقاق بسازد: `report` + `chat` (۳۰ روزه) + `transit`
(۱۲ماهه، همان چارت). یک نگاشت `action → [kinds]` لازم است، نه یک `kind` تکی.
