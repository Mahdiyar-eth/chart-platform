## ۳. 🟡 گیت‌هایی که سبزند ولی باریک‌تر از مشخصات

### گیت ۳ — «صفر کلاس هش» با **تغییر نام** پاس شد
```
grep "st-[0-9a-f]{8}" app/templates/   →  ۰      ← گیت پاس
grep "u-[0-9a-f]{6,8}"  app/templates/   →  ۵۶۲   ← همان مسئله، پیشوند جدید
```
و حجم CSS **بیشتر** شد، نه کمتر:
```
قبل:  base 218 · components 150 · generated 627 · tokens 133 · utilities  57  = ۱۱۸۵
بعد:  base 223 · components 152 · generated 627 · tokens 183 · utilities 679  = ۱۸۶۴  (+۵۷٪)
```
ضمناً حالا **دو مقیاس موازی** داریم: `--font-size-xs` و `--fs-xs` · `--radius-sm` و `--r-sm` ·
`--shadow-1` و `--sh-1` · `--line-tight` و `--lh-tight`. و **۵۴ توکن ماشینی**
(`--x-ra…`, `--w-d…`) هنوز هست. لایهٔ توکن الان **مبهم‌تر** از قبل است، نه شفاف‌تر.

> انصافاً: هرمس خودش این را در NARROWED نوشت («ادغام alias های `u-*` … ادامهٔ تدریجی»).
> پس پنهان نشده — ولی گیت نهایی نباید سبز اعلام می‌شد.

کتابخانهٔ `ui/`: ۶ کامپوننت از ۱۰ (`product_card`, `skeleton`, `toast`, `sheet` نیستند).

### گیت ۵ — سوییپ: ۱۰۰٪ OK نتیجهٔ نمونه‌گیری است
گزارش: ۹۰ کلیک روی ۹ صفحه، `{'OK': 90}`.
من همان ابزار را روی **همهٔ** کنترل‌های ۴ صفحه اجرا کردم:
```

/plans     controls= 63  → OK:60  DEAD:3
/today     controls= 27  → OK:26  DEAD:1
/synastry  controls= 28  → OK:25  DEAD:3

```
**انصافاً: هر ۱۰ مورد باگ نیستند** — یا لینکِ خودِ همان صفحه‌اند («خانه» روی `/`،
«محصولات» روی `/plans`) یا تاگل تم/منو که فقط attribute عوض می‌کنند (هر دو
`aria-label` درست دارند). یعنی نقص ابزار است، نه سایت.
ولی نکته این است: `/plans` به‌تنهایی ۶۳ کنترل دارد و سوییپ ۱۰ تا از هر صفحه
برداشته. **۹۰/۹۰ OK یک واقعیت نیست، یک نمونه است.**

### گیت ۷ — ابزار a11y نمی‌تواند قرمز شود
```python
except Exception as e:
    findings.append({"page": path, "theme": theme, "error": str(e)[:150]})
...
reds = [f for f in findings if f.get("critical_or_serious")]
return 0 if not reds else 1
```
یک اجرا که در **همهٔ** صفحات خطا بدهد، هیچ `critical_or_serious` ندارد ⇒
`reds` خالی ⇒ **`RED 0` چاپ می‌کند و ۰ برمی‌گرداند.** در محیط من هر ۲۰ اجرا
ERROR داد (خروجی شبکه به prod مسدود است) و اسکریپت باز هم «RED 0» گفت.
> نتیجهٔ a11y واقعاً تمیز است (خودم مستقل چک کردم) — ولی **این گیت نمی‌تواند
> آن را نگه دارد.** دقیقاً همان قانون ۴ پلن: ابزاری که قرمز نمی‌شود، سبزبودنش خبر نیست.
> رفع: `error` هم باید در `reds` بیاید.

## ۶. جمع‌بندی

**این بهترین دور کاری این پروژه بود.** برخلاف سه دور قبل که ۲٪ CSS عوض کردند،
این بار تغییر واقعی و قابل‌اندازه‌گیری است: اسکرول از ۸۳ms به **۱۷ms**،
`backdrop-filter` از ۲۹ به **۲**، HTML از ۷۰KB به **۳۳KB**، `/plans` از ۶۶۲۶px به
**۴۲۷۳px** با ساختار نیت‌محور، صفر خطای a11y، و **هر ۷ بند مالی/UI بازِ R14 که
با اجرا تأیید کردم بسته شده‌اند** — با ۱۴ تست بیشتر و هیچ تست حذف‌شده.

اما «تمام شد» هنوز دقیق نیست:
1. **چهار بند اعلام‌شده انجام نشده‌اند** (D7، D9، D12، `generated.css`) و در
   NARROWED هم نیامده‌اند — این‌ها کوچک‌اند و در یک نشست بسته می‌شوند.
2. **گیت ۳ با تغییر نام پاس شد.** ۵۶۲ کلاس هش هنوز هست و CSS ۵۷٪ بزرگ‌تر شده.
   کار واقعی W1.2 باقی است (خودش هم گفته).
3. **گیت ۷ نمی‌تواند قرمز شود** — یک `except` که خطا را با موفقیت یکی می‌گیرد.
4. **پوشش گیت ۴ و ۵** ۱۴٪ صفحات و نمونه‌ای است، نه کامل.

پیشنهاد من برای بستن پرونده — یک دور کوتاه و مشخص، نه یک پلن بزرگ دیگر:
> D7 · D9 · D12 · حذف `generated.css` · اصلاح `except` در `axe_audit.py` ·
> افزودن بقیهٔ صفحات به `PAGES` در `page_gate.py` · سوییپ روی **همهٔ** کنترل‌ها
> با whitelist برای لینکِ خودِ صفحه و تاگل‌های attribute-only.

بعد از آن، «تمام» واقعاً تمام است.
