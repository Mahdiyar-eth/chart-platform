## ۱. یافته‌های P0 — قبل از لانچ باید بسته شود

### P0-1 · `/api/purchase` برای دو محصول جدید **اعتبار می‌گیرد و هیچ‌چیز تحویل نمی‌دهد**

`app/main.py:981`
```python
_CHART_SCOPED_PREFIXES = ("report", "transit", "rectify", "synastry")
```
`solar_return` و `relocation` در این تاپل **نیستند** — در حالی که هر دو chart-scoped‌اند.

اجرای واقعی (کاربر با ۵۰ اعتبار):
```
POST /api/purchase {solar_return}  -> 200  remaining 41   ent: solar      chart_id = None
POST /api/purchase {relocation}    -> 200  remaining 35   ent: relocation chart_id = None
POST /api/purchase {report_full}   -> 400  chart_id_required        ← رفتار درست
GET  /api/solar/{chart}       -> 402 «چارت سالیانه با ۹ اعتبار باز می‌شود»
GET  /api/relocation/{chart}  -> 402
```
۱۵ اعتبار کم شد، هیچ محصولی باز نشد، و سیستم دوباره پول می‌خواهد. `entitlements.has()`
درست عمل می‌کند (خط ۵۷: استحقاق بدون chart_id هیچ چارتی را باز نمی‌کند) — یعنی این
استحقاق **مرده به دنیا می‌آید**.

چرا تست‌ها نگرفتند: `tests/test_new_products_e2e_w15.py:61` از مسیر اختصاصی
`/api/solar/purchase` با `chart_id` صریح خرید می‌کند؛ مسیر `/api/purchase` هرگز تست نشد.
گیت کاتالوگ هم همان اشتباه را تکرار می‌کند (`chart_id="CHX" if startswith(("report","transit","synastry"))`).

> امروز دکمهٔ `/plans` سمت کلاینت `chart_id` را می‌فرستد، پس کاربر معمولی هنوز ضرر نمی‌کند.
> ولی گاردِ سمت سرور که برای هر محصول chart-scoped دیگری وجود دارد، برای این دو نیست.
> **رفع: افزودن `"solar_return"`/`"relocation"` به همان تاپل + یک تست روی `/api/purchase`.**

### P0-2 · پیش‌نمایش رایگان، پاسخِ **بدونِ سؤال** را برای همیشه کش می‌کند

`app/main.py:808` — در مسیر شکست هم `_cache_set(insights)` صدا زده می‌شود، و کش
عمداً بدون TTL است.

```
شبیه‌سازی LLM قطع →  HTTP 200 | has question: False
redis:  cache key exists: 1 | TTL: -1  (یعنی هرگز منقضی نمی‌شود)
```
هیچ نقطهٔ ابطالی در کل `app/` وجود ندارد (`grep freepreview` فقط سه اشاره + یک تست).
یعنی **یک خطای گذرای LLM در اولین بازدید = آن چارت تا ابد سؤال کاربر را جواب نمی‌دهد.**
و اولین بازدید دقیقاً همان لحظه‌ای است که کاربر تازه سؤالش را نوشته.

**رفع: در مسیر شکست یا اصلاً کش نکن، یا با TTL کوتاه (مثلاً ۱۵ دقیقه) کش کن؛
کش دائمی فقط برای نتیجهٔ موفق.**

### P0-3 · شکایت اصلی مالک هنوز **نصفه** رفع شده است

مالک نوشته بود: «اون سؤالی که پرسیده میشه و **اون گزینه‌هایی که انتخاب می‌کنه** هیچ‌کدام در خروجی نیست».

اجرای واقعی روی یک چارت که با سؤال + دو حوزهٔ تمرکز ساخته شد:
```
GET /api/charts/{id}/preview
KEYS: ['big_three','element_summary','full_report_teaser','insights','next_transit','patterns']
personal_question: None      question_answer: None
```
- **سؤال** فقط داخل شاخهٔ `if enriched:` به payload اضافه می‌شود (`main.py:803`).
  با `ENRICH_INSIGHTS=0` یا هر شکست LLM، کلید اصلاً وجود ندارد و
  `<p x-text="preview.personal_question">` خالی می‌ماند.
- **`focus_areas` در هیچ قالبی رندر نمی‌شود** — `grep focus app/templates/chart.html` = صفر.
  حوزه‌های انتخابی فقط بی‌صدا وارد پرامپت LLM می‌شوند.

**رفع: سؤال و حوزه‌های انتخابی را در خروجی *قطعی* (غیر‌LLM) هم echo کن —
این دو رشته متعلق به خود کاربرند و هیچ هزینه‌ای ندارند.**
