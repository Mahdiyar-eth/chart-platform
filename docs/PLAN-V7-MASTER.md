## بخش ۰ — تحلیل گزارش ChatGPT (چه چیزی درست است، چه چیزی جا مانده)

گزارش `CHARTNEGAR_MASTER_AUDIT_AND_HERMES_PLAN.md` را کامل خواندم. ارزیابی من:

**✅ نقاط قوت گزارش (تأیید می‌کنم):**
- ساختار «Verify → Complete → Test → Stage → Deploy → Launch» درست و الزامی است.
- تأکید بر «do not rewrite working core» (موتور نجومی + Swiss Ephemeris) صحیح است — این را دست نمی‌زنم.
- تأکید بر «کد موجود ≠ تمام‌شده» درست است — باید runtime verification شود.
- چک‌لیست Go/No-Go کامل و قابل اجراست.

**⚠️ چیزی که ChatGPT ندید (چون فقط EXECUTION-REPORT را خواند، نه کد):**
- دو باگ واقعی «وعده‌ی شکسته» که من با خواندن کد **قطعی تأیید کردم** (بخش ۱).

**🔴 یک ریسک که باید صادقانه بگویم:**
- گزارش می‌گوید ۸۳ تست پاس شده. این درست است، **ولی تست‌ها end-to-end نیستند.** تست «کد وجود دارد» را پاس می‌کنند، نه «feature واقعاً کار می‌کند». به همین دلیل Phase 0 (Verify) را اول می‌گذارم.

## بخش ۱ — باگ‌های تأییدشده (قبل از هر کار جدید باید فیکس شوند)

### باگ ۱: «حوزه‌های مورد علاقه» (focus_areas) — وعده‌ی شکسته
- فرم می‌گوید: «این انتخاب ترتیب و تأکید بخش‌های گزارش را شخصی‌سازی می‌کند»
- **واقعیت (تأیید با کد):** فقط در «گفت‌وگو با چارت» (چت) استفاده می‌شود. در اینسایت‌های رایگان و تولید گزارش **صفر ارجاع** دارد.
- **فیکس:** این انتخاب را واقعاً در خروجی استفاده کنیم (ترتیب/تأکید بخش‌ها + اینسایت‌های رایگان) یا متن فرم را صادقانه اصلاح کنیم.

### باگ ۲: «سؤال شخصی اختیاری» (question) — وعده‌ی شکسته
- فرم می‌گوید: «در گزارش کامل، پاسخ این سؤال تفسیر می‌شود»
- **واقعیت (تأیید با کد):** سؤال **حتی از مرورگر ارسال نمی‌شود** (JS فقط `focus_areas` را می‌فرستد)، API پارامتر `personal_question` ندارد، و هیچ‌جا ذخیره/پاسخ داده نمی‌شود.
- **فیکس:** سؤال را ارسال + ذخیره + در گزارش کامل پاسخ دهیم، یا گام را حذف کنیم. (پیشنهاد من: واقعاً پیاده‌سازی کنیم — ارزش افزوده واقعی دارد.)

### این دو باگ مهم‌اند چون:
- کاربر چیزی را انتخاب/می‌پرسد و **هیچ نتیجه‌ای نمی‌گیرد** → حس «فال‌بازی و الکی» می‌دهد — دقیقاً ضد برند تأملی/صادقانه‌ی چارت‌نگار.

## بخش ۲ — نقشه راه (فاز ۰ تا ۹)

> هر فاز فقط با Acceptance Criteria مشخص «تمام» می‌شود؛ نه با وجود کد.

### Phase 0 — Freeze & Verify (اولین قدم)
- فریز baseline (git tag) + اجرای همه تست‌ها
- **Inventory کامل:** همه routeها، migrationها، env vars، cron، worker، storage، payment
- **اسکن «وعده‌های شکسته»** (مثل focus_areas/question) در کل فرم‌ها و صفحه‌ها
- **بررسی تیکه‌به‌تیکه صفحه چارت رایگان** (فاجعه‌ای که گفتی) + لیست دقیق مشکلات UI/UX
- **Acceptance:** baseline reproducible + تست‌ها پاس + لیست کامل مشکلات

### Phase 1 — امنیت / مالکیت
- اثبات مالکیت با تست منفی واقعی: chart/report/PDF/order کاربر A → کاربر B → 403
- OTP، CSRF، CORS، کوکی‌ها، authorization سفارش
- **Acceptance:** همه تست‌های منفی 401/403 برگردانند

### Phase 2 — پرداخت / Fulfillment
- E2E پرداخت + idempotency وب‌هوک + report enqueue + worker retry + degraded
- اشتراک هفتگی fulfillment واقعی
- **Acceptance:** کاربر پرداخت‌کننده دقیقاً یک fulfillment معتبر بگیرد

### Phase 3 — داده / Recovery
- Alembic + بکاپ + restore + reconciliation + DLQ
- **Acceptance:** سرور تازه با مستندات قابل بازسازی باشد

### Phase 4 — Frontend / UX ← **اینجا خواسته‌های خاص توست**
- **صفحه چارت رایگان:** بازطراحی کامل (hierarchy: هویت → ۳ insight کلیدی → توضیح → CTA)
- **توضیح ساده‌ی هر نمودار:** گراف جنبه‌ها، دونات عناصر، نمودار خانه‌ها، timeline ترانزیت — هر کدام با «این نمودار چی می‌گوید» به زبان عموم
- **لایه DeepSeek:** اینسایت‌های رایگان را جذاب‌تر و قابل‌فهم‌تر کند (هزینه کم + fallback قطعی)
- **آموزش نجوم:** رفع contrast/خوانایی + تکمیل ۳۷ صفحه + ساختار Beginner/Intermediate/Advanced
- **FAQ/راهنما/درباره:** خیلی کامل‌تر
- **Acceptance:** QA روی موبایل واقعی تو

### Phase 5 — محتوا
- ۵۰ مقاله درجه‌یک (فیکس ناقص‌ها + ۱۶ جدید) + توضیح ساده‌ی هر اصطلاح + تصویر FLUX + SEO کامل
- **Acceptance:** هر مقاله چک‌لیست کامل (بخش ۲۸ گزارش) را پاس کند

### Phase 6 — مارکتینگ (لید مگنت + analytics + funnel + newsletter)
### Phase 7 — برند (motif + visual system)
### Phase 8 — Staging (دیپلوی روی سرور استیجینگ + تست کامل)
### Phase 9 — Production (فقط بعد از Go)

## بخش ۴ — Go/No-Go (خلاصه)

**GO فقط اگر:** همه تست‌های بحرانی پاس + مالکیت اثبات‌شده + پرداخت اثبات‌شده + fulfillment اثبات‌شده + بکاپ/restore اثبات‌شده + دیپلوی reproducible + رولبک تست‌شده + مانیتورینگ فعال + محتوا کامل + بدون testimonial جعلی + موبایل پاس.

**NO-GO اگر:** منبع anonymous با ID قابل دسترسی باشد + feature پولی بدون fulfillment + پرداخت قابل جعل + گزارش نشت‌کننده + restore هرگز تست نشده + دیپلوی دستی/غیرقابل‌تکرار + خطای بحرانی غیرقابل‌مشاهده + محتوای placeholder + UI ناخوانا در موبایل.

۲. خروجی Phase 0 (لیست کامل مشکلات + باگ‌ها) را برایت می‌فرستم.
