## بخش ۳ — تصحیحی که باید در کد ثبت شود

کامنت فعلی `main.py:1272` می‌گوید بدون commit «همهٔ درخواست‌های همزمان claim می‌کنند و
درگاه N بار verify می‌شود». **این نادرست است.** با کد قبل از R13 و ۴ نخ همزمان:

```
thread 0 -> CLAIMED+verified (blocked 0.00s)
thread 1..3 -> lost -> redirect (blocked 2.01s هرکدام)
gateway verify() would run: 1 time
```

قفل سطری PostgreSQL از قبل مانع دوباره‌verify می‌شد. آنچه **واقعاً** خراب بود: هر
بازنده یک کانکشن دیتابیس را به‌اندازهٔ کل تأخیر درگاه نگه می‌داشت ⇒ خطر ته‌کشیدن
connection pool. بعد از فیکس: **۰٫۰۲ ثانیه**. **فیکس درست است — فقط توضیحش را تصحیح کن.**

### W2.1 — هویت
- **پس‌زمینه:** یک آسمان عمیق واقعی با گرادیان ظریف؛ نه مشکی تخت، نه بنفش اشباع.
- **ستاره‌ها:** فقط **یک** لایهٔ CSS استاتیک (بدون JS، بدون canvas، بدون انیمیشن مداوم).
  یک SVG کاشی‌شده یا `radial-gradient` تکرارشونده. **صفر هزینهٔ زمان اجرا.**
- **طلا** لهجه است نه رنگ متن: فقط CTA اصلی، عدد اعتبار، و نشانگر فعال.
- **شیشه** فقط روی **حداکثر ۳ سطح در هر صفحه** — نه ۲۷ تا (بخش ۶).
- **چرخ چارت** قهرمان بصری است: بزرگ‌تر، تمیزتر، با فاصلهٔ نفس‌گیر دورش.

### W2.2 — تایپوگرافی
Vazirmatn بماند (خودمیزبان + `font-display:optional` — درست است).
مقیاس ماژور ترد، `line-height` ۱٫۷ برای متن فارسی، طول خط ۶۰–۷۵ کاراکتر،

- هیچ انیمیشن `infinite` روی عنصری که کنترل تعاملی دارد (درسِ R12).
- `@media (prefers-reduced-motion: reduce)` همه را خاموش کند.

## بخش ۸ — W5: آنچه در بک‌اند/فرانت مانده

| # | کار |

## بخش ۹ — 🔒 پروتکل راستی‌آزمایی سخت‌گیرانه (اینجاست که «تمام» معنا پیدا می‌کند)

> **قانون مطلق: هیچ تسکی «انجام‌شده» نیست مگر خروجی ابزار را در گزارش بچسبانی.
> جملهٔ «تست کردم و درست است» بدون خروجی = تسک انجام‌نشده.**

### ۹.۱ — دروازهٔ هر تسک (Definition of Done برای یک تسک)
هر تسک باید این ۶ چیز را داشته باشد:
1. **تست RED** — قبل از کد بنویس و خروجی قرمزش را بچسبان.
2. **کد** — دیف < ~۲۵۰ خط.
3. **تست GREEN** — خروجی سبز را بچسبان.
4. **`bash scripts/ci.sh`** — خروجی کامل، `CI_EXIT=0`.
5. **اثبات مرورگری** (برای هر تسک UI) — اسکرین‌شات ۳۹۰px + ۱۲۸۰px، **هر دو تم**.
6. **یک کامیت با `[<ID>] <خلاصه>`**.

### ۹.۲ — دروازهٔ صفحه (برای هر صفحهٔ بازطراحی‌شده)
یک اسکریپت `scripts/page_gate.py` بنویس که برای هر صفحه این‌ها را می‌سنجد و
**با کد خروج غیرصفر شکست می‌خورد** (نه مثل `w16_browser_qa.py` که `sys.exit(0)` داشت):

```
□ HTTP ۲۰۰ (یا ریدایرکت موردانتظار — و اگر لاگین‌گیتد است، واقعاً لاگین کن)
□ overflow افقی = ۰  در ۳۶۰ / ۳۹۰ / ۴۳۰ / ۷۶۸ / ۱۲۸۰ / ۱۹۲۰
□ هیچ عنصری زیر نوار پایین پنهان نشود  (تست همپوشانی)
□ کنتراست متن ≥ ۴٫۵:۱ (AA) در هر دو تم — با axe-core
□ هر کنترل تعاملی ≥ ۴۴×۴۴px
□ صفر خطای کنسول، صفر ۴۰۴ منبع
□ FCP و p95 فریم اسکرول زیر بودجهٔ بخش ۶ (با ۴× CPU throttle)
□ backdrop-filter ≤ ۶ ، عناصر انیمیشن‌دار ≤ ۲۰
□ اسکرین‌شات ذخیره در docs/qa/redesign/<page>-<width>-<theme>.png
```

### ۹.۳ — سوییپ تعاملی واقعی (نه ۸۴/۸۴ OK)
> در R12 من همان ابزار را روی همان صفحات اجرا کردم و در ۳۴ کلیک نمونه
> **۷ تا DEAD و ۱ تا BROKEN** گرفتم، در حالی که سند می‌گفت ۸۴/۸۴ OK.
> **این بار عدد باید بازتولیدپذیر باشد.**

- **همهٔ** کنترل‌های هر صفحه (نه نمونه) — `/` تنها ۶۳ کنترل دارد.
- در **۵ حالت**: مهمان · واردشده بدون اعتبار · با اعتبار · با محصول خریداری‌شده · ادمین.
- خروجی: جدول کامل با ستون‌های `صفحه | کنترل | نتیجه | شاهد`.
- **هر DEAD یا BROKEN یا باید رفع شود یا با دلیل صریح در گزارش بیاید.**
- معیار OK همان معیار سخت‌گیرانهٔ S2 (متن دیدنی/توست/ناوبری) بماند —
  و «فعالیت شبکه» را از معیار OK **حذف کن**: پولینگ پس‌زمینه دکمهٔ مرده را OK نشان می‌دهد.

### ۹.۴ — مسیرهای پول (با اسکیل `credit-economy`)
هر کدام سرتاسر و با ledger:
```
□ چارت رایگان بدون ورود → ثبت‌نام → چارت claim می‌شود
□ خرید پک اعتبار (واردشده) → موجودی + ردیف ledger
□ خرید پک اعتبار (مهمان) → طبق تصمیم D2 (الف یا ب) — و اعتبار واقعاً می‌رسد
□ هر ۱۲ محصول: قبل از خرید گیت، بعد از خرید تحویل، ledger دقیق
□ LANCH20: روی گزارش عمیقِ اول ✓ · روی پک اعتبار ✗ · بار دوم ✗
□ استرداد → اعتبار برمی‌گردد → مجموع ledger == users.credits
□ ناوردا: sum(ledger) == users.credits برای هر کاربر تست
```

### ۹.۶ — دروازهٔ نهایی («واقعاً تمام»)
**فقط وقتی این ۱۰ مورد همزمان درست‌اند بگو تمام شد:**
```
 ۱. bash scripts/ci.sh  →  CI_EXIT=0   (خروجی کامل چسبانده شده)
 ۲. ران واقعی GitHub Actions روی همان کامیت HEAD  →  success  (شمارهٔ ران را بنویس)
 ۳. grep "st-[0-9a-f]\{8\}" app/templates/  →  ۰ نتیجه
 ۴. page_gate.py روی همهٔ ~۵۰ صفحه  →  exit 0
 ۵. سوییپ تعاملی کامل  →  صفر DEAD و صفر BROKEN رفع‌نشده
 ۶. هر ۷ سنجهٔ بودجهٔ عملکرد (بخش ۶) زیر هدف
 ۷. axe-core روی ۱۰ صفحهٔ اصلی  →  صفر خطای critical/serious
 ۸. هر ۷ بند مسیر پول (۹.۴) سبز

۱۰. deploy روی prod + راستی‌آزمایی زنده با curl روی رشته‌های نشانگر
```

## بخش ۱۱ — قوانینی که نقض‌شان کار را باطل می‌کند

1. **خطوط قرمز `CLAUDE.md`** — موتور نجومی، حذف‌نکردن تست، قیمت بدون تأیید مالک،
   بدون secret، بدون زبان «فال/پیش‌بینی/طالع‌بینی».
2. **هیچ تستی ضعیف نشود.** اگر تستی باید تغییر کند، در گزارش بنویس **چه پوششی از
   دست رفت** و **چه تستی جایش آمد**. (درسِ R14: تست نگهبان LANCH20 حذف شد و باگ رد شد.)
3. **هیچ ادعایی بدون خروجی ابزار.**
4. **هیچ `sys.exit(0)` در اسکریپت QA.** ابزاری که نمی‌تواند قرمز شود، سبزبودنش خبر نیست.
5. **هیچ انیمیشن `infinite` روی عنصر تعاملی.**
6. **اگر چیزی نیاز به کلید/حساب بیرونی دارد → BLOCKED اعلام کن، اختراع نکن.**
7. **هزینه:** هیچ اندپوینت پولی LLM در تست. `ENRICH_INSIGHTS=0`.
8. **اگر نمی‌توانی یک بند را ببندی، صریح بنویس «نبستم، چون…».** گزارش ناقصِ صادق از
   گزارش کاملِ نادرست بی‌نهایت بهتر است.
