```
grep -rln "playwright\|\.click(" tests/*.py   →   خالی
```

**یعنی:** ما API را خوب تست کرده‌ایم و صفحات را خوب **رندر** کرده‌ایم،
اما هیچ‌کس هرگز برنامه را مثل یک **انسان استفاده نکرده** — دکمه نزده، فرم پر نکرده،
و یک عملیات ادمین را از اول تا آخر تمام نکرده.

`scripts/ui_audit.py` صفحه را باز می‌کند و **اندازه می‌گیرد** (کنتراست، هدف لمسی، اسکرول)،
ولی **هیچ تعاملی نمی‌کند**.

**اثبات زندهٔ این شکاف:** از ۴ اندپوینت ادمین که هیچ تستی ندارند، یکی
`/api/admin/credit-report` است — و همان یکی امروز در ممیزی من **۵۰۰** داد.
تصادفی نیست: **تست‌نشده = خراب.**

هر سه باگ بزرگی که در دو ممیزی آخر پیدا شد، یک ریشهٔ مشترک دارند:
> **کد وجود دارد، صفحه رندر می‌شود، ولی هیچ‌کس هرگز آن عمل را تا انتها انجام نداده.**

## بخش ۱ — قوانین این پلن (متفاوت با دورهای قبل)

### ۱.۱ قانون «هیچ بندی باریک نمی‌شود»
در پلن اولیه، بند `A4` می‌گفت «`plans.html` را بازنویسی کن: جدول واحد اعتباری».
اجرا شد به: «چیپ اعتبار + `credit_cta`» و در کامیت نوشته شد «plans.html already has credit packs».
⇒ **صفحهٔ اصلی فروش هنوز `/api/orders` تومانی را صدا می‌زند و `/api/purchase` اعتباری را هرگز.**

**از این پس:** اگر بندی را کوچک‌تر از متنش اجرا کردی، **حق داری** — ولی باید در گزارش
زیر تیتر `NARROWED` بنویسی: «بند X را به Y محدود کردم، چون…». سکوت ممنوع.
هر بند `NARROWED` در بازبینی بعدی دوباره باز می‌شود.

### ۱.۲ قانون «مدرک = خروجی، نه ادعا»
هر آیتم چک‌لیست باید یکی از این‌ها را داشته باشد: خروجی دستور · اسکرین‌شات · شمارهٔ تست.
«بررسی شد ✅» بدون مدرک = انجام‌نشده.

### ۱.۳ قانون «حالت کاربر»
هر صفحه در **۶ حالت** رفتار متفاوت دارد. تست فقط در یک حالت = تست ناقص:

| # | حالت |
|---|---|
| G | مهمان، بدون چارت |
| C | مهمان، با چارت (کوکی capability) |
| U | لاگین‌شده، بدون چارت |
| U+C | لاگین‌شده، با چارت، **۰ اعتبار** |
| U+$ | لاگین‌شده، با چارت، **اعتبار کافی** |
| U+P | لاگین‌شده، با محصول **خریداری‌شده** (گزارش/چت/گذر) |
| A | ادمین |

### ۱.۴ خط قرمزها (بدون تغییر)
موتور نجومی · حذف/اسکیپ تست · قیمت‌های تومانی بدون تأیید مالک · سکرت در کد · زبان «فال/پیش‌بینی».

### `P2-1` — ساخت سیاههٔ تعاملی خودکار (اول این)
**فایل جدید:** `scripts/interaction_inventory.py`

با Playwright، برای **هر صفحه × هر حالت کاربر (بخش ۱.۳)**، هر عنصر تعاملی را استخراج کن:
```
button · a[href] · input · select · textarea · [role=button] · [onclick] · [x-on:click] · <details>
```
برای هرکدام ثبت کن: `صفحه · حالت · نوع · متن/برچسب · selector یکتا · مقصد (href/handler)`

**خروجی:** `docs/qa/INTERACTION-INVENTORY.md` + `.json`

### `P2-2` — کلیک‌کردن واقعی همهٔ آیتم‌ها
**فایل جدید:** `scripts/interaction_sweep.py` + گزارش `docs/qa/INTERACTION-SWEEP.md`

برای هر آیتم سیاهه، اجرا کن و ثبت کن:

| چک | قبولی |
|---|---|
| کلیک/سابمیت بدون خطای JS | صفر `pageerror` |
| ناوبری به مقصد درست | کد وضعیت ۲۰۰/۳۰۳ درست، نه ۴۰۴/۵۰۰ |
| حالت بارگذاری دارد | دکمهٔ عملیاتی هنگام کار غیرفعال + نشانگر |
| نتیجهٔ قابل مشاهده | یا محتوا عوض شد، یا پیام/توست نشان داده شد |
| بازگشت‌پذیری | بعد از عمل، کاربر در بن‌بست نیست |
| در هر دو تم | تیره و روشن |

**دسته‌بندی نتیجه:** `OK` · `BROKEN` (خطا/۵۰۰) · `DEAD` (هیچ اتفاقی نمی‌افتد) ·
`SILENT` (کار می‌کند ولی بازخورد ندارد) · `BLOCKED` (نیاز به کلید بیرونی)

**پذیرش:** پوشش **۱۰۰٪** سیاهه. هر آیتم غیر از `OK` یک ردیف در جدول یافته‌ها با فایل:خط.

### `P2-3` — 🔴 پنل ادمین، دکمه‌به‌دکمه (بیشترین بدهی)
**۵۰ کنترل + ۲۶ تابع JS + ۲۹ اندپوینت، ولی فقط ۲ فایل تست.**

برای **هر** بخش پنل، چرخهٔ کامل را انجام بده (نه فقط باز کردن صفحه):

| بخش | چرخهٔ کامل که باید تمام شود |
|---|---|
| آمار و KPI | بارگذاری · اعداد با DB بخوانند |
| **گزارش مالی اعتبار** | 🔴 الان **۵۰۰** (`Q2`) — بعد از فیکس: اعداد درست |
| قیمت‌های اعتبار | تغییر قیمت → ذخیره → **تأثیرش در سمت کاربر دیده شود** |
| اعطای دستی اعتبار | اعطا → موجودی کاربر عوض شود → ردیف AuditLog |
| CMS مقالات | ساخت → ویرایش → پیش‌نمایش → انتشار → حذف → **بازگردانی نسخه** |
| CMS صفحات | همان چرخه (`/api/admin/content/pages/{key}` بدون تست است) |
| رسانه | آپلود → نمایش در مقاله → حذف |
| کوپن | ساخت → استفاده در خرید واقعی → سقف مصرف → انقضا |
| سفارش‌ها و ریفاند | مشاهده → ریفاند → **استحقاق باطل شود** |
| تست LLM | `/api/admin/llm/test` (بدون تست است) — با ماک |
| سکرت‌ها | ذخیره → reveal → عدم نشت در لاگ |
| سلامت و صف | health · وضعیت worker · صف گزارش |
| پرامپت‌ها | ویرایش → نسخه‌بندی → اعمال |

**پذیرش:** جدولی با ۱۳ ردیف، هرکدام: `چرخه · نتیجه · مدرک`. هیچ ردیفی بدون مدرک.

### `P2-4` — سفرهای کامل کاربر (۹ سفر، سرتاسری)
هر سفر از **صفحهٔ اول** شروع می‌شود، با **کلیک**، نه با curl:

1. **کاربر تازه:** فرود → چارت رایگان → دیدن بینش → ثبت‌نام → claim چارت → داشبورد
2. **خرید اعتبار:** `/plans` → انتخاب پک → پرداخت (ماک) → موجودی افزایش → دفتر درست
3. **گزارش:** خرید با اعتبار → تولید → نوار پیشرفت → دانلود PDF **و** DOCX **و** صوت
4. **گزارش طلایی:** خرید ۱۴ اعتبار → **چت باز شود** + **گذر ۱۲ماهه باز شود** (`Q1`)
5. **گذر:** انتخاب ۳/۱۲ ماه → خرید → تایم‌لاین → ماه‌های جمع‌شونده → افزودن به تقویم
6. **چت:** بستهٔ پیام → ارسال → مصرف شمارش شود → پیام آخر → پیشنهاد خرید مجدد
7. **کاوش و سیناستری و بازبینی ساعت:** هرکدام تا خروجی نهایی
8. **شکست و بازیابی:** LLM را بشکن → پیام قابل‌فهم → **اعتبار برگردد** → دفتر درست
9. **پایان چرخه:** خروجی داده → حذف حساب → همه‌چیز پاک شود → ثبت‌نام دوباره ممکن باشد

**پذیرش:** ۹ سفر × (موبایل ۳۹۰px + دسکتاپ) با اسکرین‌شات هر گام کلیدی.
