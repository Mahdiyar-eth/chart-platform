## ⛔ قبل از هر کاری این را بخوان

تشخیص دور قبل («گوشی کاربر روی تم روشن است») **ریشه نبود**.
ریشه یک خط CSS خراب است که **۵۸٪ استایل‌شیت را روی کل سایت می‌کشد.**

### مدرک — اجرای واقعی روی `e670de4`

```
app/static/css/utilities.css خط ۳۲۲:

.u-884f21bb{color:${ok ? 'var(--green-ok)' : 'var(--danger-bright)'}
                   ▲ template literal جاوااسکریپت           ▲ } بسته نشده

شمارش آکولاد در همان خط:   { = ۲   } = ۱     ← نامتوازن
```

نتیجه در مرورگر واقعی (Chromium، `document.styleSheets`):
```
تعداد قواعد .u- در فایل        : ۶۱۱
تعداد قواعدی که مرورگر پارس کرد: ۳۰۲
آخرین قاعده‌ای که پارس شد      : .u-884f21bb   ← دقیقاً همان خط
قواعد مُرده بعد از این نقطه    : ۳۵۵  (۵۸٪)
```

**یعنی ۳۵۵ کلاس روی هر صفحهٔ سایت هیچ استایلی ندارند.** به همین دلیل:
- آیکون گفت‌وگو در صفحهٔ اصلی **۳۰۰×۱۵۰ پیکسل** رندر می‌شود
  (قاعده‌اش `.u-d1039ed9{width:42px;height:42px}` است ولی **هرگز پارس نشده**)
- فاصله‌ها، رنگ‌ها و اندازه‌های ده‌ها عنصر دیگر به حالت پیش‌فرض مرورگر برمی‌گردند
- همان چیزی که مالک در اسکرین‌شات‌ها می‌بیند

### این خطا از کجا آمد؟
از همان مرحلهٔ «تغییر نام مکانیکی `st-` → `u-`».
در `generated.css:38` همین محتوا هست ولی **سالم**:
```css
.st-884f21bb{ color:${ok ? ... }; }        ← ; و } دارد ⇒ فقط یک declaration بی‌اثر
.u-884f21bb{color:${ok ? ... }             ← ; و } حذف شده ⇒ خطای مرگبار پارسر
```
اسکریپت تغییر نام، `;` و `}` را برداشته و یک اعلانِ بی‌ضرر را به خطای کشنده تبدیل کرده.

## فاز ۰ — سه رفع، امروز (کمتر از یک ساعت)

### 🔴 U0-1 · خط ۳۲۲ را درست کن
منبعش یک استایل اینلاین ساخته‌شده با JS بوده؛ اصلاً نباید در CSS باشد.
```
۱. خط ۳۲۲ را از utilities.css حذف کن (و خط ۳۸ generated.css اگر هنوز هست)
۲. در قالبی که از این کلاس استفاده می‌کند، رنگ را با دو کلاس واقعی بگذار:
   .is-ok{color:var(--green-ok)}  .is-bad{color:var(--danger-bright)}
   و در JS بین این دو سوییچ کن، نه با ساختن رشتهٔ CSS.
۳. صحت را با همین سنجه ثابت کن:
   قواعد پارس‌شدهٔ مرورگر باید == تعداد قواعد فایل باشد.
```

### 🔴 U0-2 · لیبل‌های نوار پایین در تم روشن نامرئی‌اند
رفع دور قبل **ناقص** بود: پس‌زمینه سرمه‌ای شد ولی رنگ متن از توکن‌های تم روشن می‌آید.
اندازه‌گیری من روی `e670de4`:

| تم | آیتم | رنگ | کنتراست | |
|---|---|---|---|---|
| روشن | «خانه» (فعال) | `rgb(95,67,0)` | **۱٫۹۴** | ❌ |
| روشن | «چارت رایگان» | `rgb(44,51,85)` | **۱٫۴۵** | ❌ |
| روشن | بقیه | سفید ۷۲٪ | ۱۷٫۷۵ | ✅ |
| تاریک | همه | — | ۱۰٫۴ تا ۱۷ | ✅ |

**رفع:** وقتی سطحِ chrome در هر دو تم تیره است، رنگ متنش هم باید از یک توکن
مستقل بیاید (`--chrome-ink`, `--chrome-ink-active`) نه از `--gold-text`/`--muted-3`
که برای زمینهٔ روشن‌اند.
> ادعای «کنتراست همهٔ لیبل‌ها ۸٫۴ تا ۱۳٫۲» برای تم روشن **درست نیست**.

### 🔴 U0-3 · محتوا از پشت نوار پایین رد می‌شود
```
background: rgba(17,22,49, 0.92)      ← ۸٪ شفاف
backdrop-filter: none                 ← بلور در R14 برای سرعت حذف شد
عناصر پشت نوار در ارتفاع نوار: SPAN.tag ، SUMMARY  ← دیده می‌شوند
```
حذف بلور درست بود (سرعت)، اما آلفا سرِ جایش ماند.
**رفع:** `background` را **کاملاً مات** کن (`alpha = 1`). بدون بلور، شفافیت روی یک
نوار ثابت فقط کثیفی تولید می‌کند. همین برای appbar بالا هم صادق است.

## فاز ۱ — گاردریل (تا این اتفاق دیگر تکرارنشدنی شود)

سه گیت کوچک. **هر سه باید کد خروج غیرصفر داشته باشند.**

| گیت | چه چیزی را می‌گیرد |
|---|---|
| **G1 · CSS-parse** | برای هر فایل CSS: تعداد قواعد فایل را با `document.styleSheets[i].cssRules.length` مقایسه کن. **نابرابر ⇒ قرمز.** این دقیقاً همان باگی است که سه دور از همهٔ گیت‌ها رد شد. |
| **G2 · unstyled-element** | هیچ `<svg>`ای نباید ۳۰۰×۱۵۰ (اندازهٔ پیش‌فرض) باشد؛ هیچ عنصر تعاملی نباید بدون قاعدهٔ منطبق باشد. |
| **G3 · chrome-contrast** | کنتراست appbar/bottomnav/drawer در **هر دو تم** ≥ ۴٫۵. دیگر «فقط تم پیش‌فرض» تست نشود. |

> درس این دور: `axe` و `page_gate` هر دو سبز بودند در حالی که ۵۸٪ CSS مرده بود.
> هیچ‌کدام «آیا استایل‌شیت اصلاً پارس شد؟» را نمی‌پرسیدند.

## فاز ۲ — بعد از فاز ۰، دوباره نگاه کن

**مهم:** بخش بزرگی از آنچه در اسکرین‌شات‌ها فاجعه به‌نظر می‌رسد، با U0-1 خودبه‌خود
درست می‌شود (۳۵۵ قاعده زنده می‌شوند). **قبل از هر طراحی جدید:**

```
۱. فاز ۰ را ببند و دیپلوی کن
۲. از ۸ صفحه در هر دو تم و ۳۹۰px اسکرین‌شات بگیر
۳. اسکرین‌شات‌ها را برای مالک بفرست
۴. تازه آن‌وقت تصمیم بگیرید چه چیزی واقعاً باید بازطراحی شود
```
هر طراحی‌ای که روی استایل‌شیتِ نصفه‌مرده انجام شود، دور بعد دوباره دور ریخته می‌شود.

## فاز ۳ — کار طراحی واقعی (فقط بعد از تأیید مالک روی اسکرین‌شات‌های فاز ۲)

به ترتیب اولویت، **هر کدام یک کامیت جدا**، و **بعد از هر کدام یک اسکرین‌شات**:

### D1 · نوار پایین (بیشترین تماس با کاربر)
- پس‌زمینهٔ مات، ارتفاع ۶۴px + `env(safe-area-inset-bottom)`
- FAB: قطر ۵۶px، وسط دقیق، لیبل زیرش خوانا در هر دو تم
- هیچ محتوایی زیرش پنهان نشود: `body{padding-bottom: calc(64px + safe-area)}`

### D2 · appbar
- مات، ارتفاع ثابت، لوگو/اعتبار/منو با فاصلهٔ یکنواخت
- چیپ اعتبار: خوانا در هر دو تم

### D3 · کارت‌ها و بخش‌ها
- **یک** سبک کارت برای کل سایت (`.card`)، نه چند نوع شیشه‌ای متفاوت
- فاصلهٔ عمودی یکنواخت بین بخش‌ها از `--space-*`
- عنوان‌ها با `text-wrap: balance`، طول خط ۶۰–۷۵ کاراکتر

### D4 · صفحهٔ `/learn` و صفحات محتوایی
لینک‌های داخل متن در اسکرین‌شات مالک با پس‌زمینهٔ خاکستری/زیرخط شکسته دیده می‌شوند —
این هم از قواعد مردهٔ فاز ۰ می‌آید. بعد از U0-1 دوباره ببین؛ اگر ماند، سبک لینک را
یکدست کن (بدون پس‌زمینه، زیرخط ظریف، رنگ برند).

### D5 · آیکون‌ها
هر `<svg>` باید `width`/`height` صریح از یک مقیاس ثابت بگیرد (۱۶/۲۰/۲۴/۳۲/۴۰).
هیچ آیکونی نباید به اندازهٔ پیش‌فرض بیفتد.

## قوانین این دور

1. **هیچ ریفکتور جدیدی شروع نکن.** ۵۶۲ کلاس `u-` هش‌نام سرِ جایشان بمانند —
   الان مسئله این نیست.
2. **هر کامیت یک چیز.** فاز ۰ سه کامیت است، نه یکی.
3. **هیچ ادعایی بدون خروجی ابزار.** برای U0-1 عدد «قواعد فایل == قواعد پارس‌شده»
   را بچسبان؛ برای U0-2 جدول کنتراست هر دو تم؛ برای U0-3 مقدار `backgroundColor`.
4. **تم روشن و تاریک، هر دو، در هر بررسی.** بدون استثنا.
5. اگر چیزی را نبستی، صریح بنویس «نبستم چون…».
6. خطوط قرمز `CLAUDE.md` سرِ جای خود.
